# ChronoVision Architecture and Decisions Log

Record significant technical and product decisions here.

This log separates:
- **Confirmed Constraints** — directly supported by the source specifications
  (`AGENTS.md`, `../guidelines.md`, `../workflow_requirements.md`).
- **Confirmed Decisions** — choices fixed by the specifications.
- **Pending Decisions / Proposals** — unresolved or proposed; not yet agreed.

See `docs/OPEN_QUESTIONS.md` for the full question set and `docs/REQUIREMENTS_TRACEABILITY.md`
for requirement IDs.

## Confirmed Constraints
- No runtime LLM or generative AI dependency.
- Event descriptions use deterministic templates.
- Each camera is processed independently.
- Tracking is limited to an individual camera; no cross-camera re-identification.
- Camera zones are predefined and camera-specific.
- Processing runs continuously while monitoring is explicitly active.
- Events can retain evidence snapshots and short video clips.
- PostgreSQL is the structured application database.
- Begin with one camera and scale after benchmarking.
- Keep video viewing separate from the analysis pipeline.
- The browser must not perform the primary video-analysis workload.
- The runtime application must not depend on OpenCode, DeepSeek, or any coding-agent
  availability.
- Long-running video inference must not run inside ordinary HTTP request handlers.
- Frame queues and rolling buffers must be bounded.

| D-36 | 2026-10-29 | **Per-activity rule semantics are explicit and conservative.** *Entry/exit:* anchor is the bbox bottom-centre; the first observation establishes presence and never emits; a crossing must be confirmed for N frames and is suppressed during cooldown; a track disappearing without an observed outward crossing emits nothing.
